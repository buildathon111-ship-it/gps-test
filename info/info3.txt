PROJECT: AGRIVISION — Browser-Based Plant Detection Prototype

GOAL
Build the first computer-vision prototype for our AGRIVISION agricultural rover project.

For now, DO NOT use the ESP32-CAM, any physical hardware, backend, database, Python server, Node.js server, or framework.

Use the laptop's built-in webcam as the temporary camera source.

The purpose of this prototype is to establish the software pipeline now, so that later the laptop webcam can be replaced by the ESP32-CAM live stream without redesigning the detection architecture.

==================================================
STRICT FILE REQUIREMENT
==================================================

The entire application must be implemented using ONLY:

1. index.html
2. style.css
3. script.js

Do NOT create:
- React
- Next.js
- Vue
- Node.js
- Python
- Flask
- Express
- TypeScript
- build systems
- npm dependencies
- package.json
- backend files
- additional HTML/JS/CSS files

The application must run directly in a modern browser.

If an external browser-compatible AI/YOLO library or model is required, load it through CDN or another browser-compatible mechanism from the HTML/JavaScript, while keeping our own project limited to the three files above.

==================================================
CORE FUNCTIONALITY
==================================================

Build a live plant-detection application.

Pipeline:

Laptop Webcam
      ↓
Live Video Frames
      ↓
YOLO/Object Detection
      ↓
Plant Detection
      ↓
Bounding Boxes
      ↓
Confidence Score
      ↓
AGRIVISION UI

The first model should focus ONLY on detecting plants.

Do NOT implement crop disease detection yet.

Do NOT implement plant species classification yet.

Do NOT implement nutrient deficiency detection yet.

This is ONLY Stage 1:
"Is there a plant in the camera view, and where is it?"

==================================================
CAMERA
==================================================

Request webcam permission using the browser MediaDevices/getUserMedia API.

Display the live camera feed prominently.

Handle:
- camera permission denied
- camera unavailable
- no camera detected
- loading state
- browser incompatibility

Provide:
[START CAMERA]
[STOP CAMERA]

Do not access the camera automatically without user interaction if browser security policies prevent it.

==================================================
PLANT DETECTION
==================================================

Use a browser-compatible YOLO/object-detection solution.

IMPORTANT:
The architecture must isolate the detection implementation behind a clean JavaScript interface.

For example conceptually:

detectFrame(frame)
    ↓
DetectionResult

The rest of the application must NOT depend directly on the YOLO implementation.

Detection result should contain information such as:

{
    className: "plant",
    confidence: 0.94,
    boundingBox: {
        x: ...,
        y: ...,
        width: ...,
        height: ...
    }
}

If a suitable plant-specific YOLO model is not available yet, create a clearly separated MOCK DETECTOR mode so that the complete UI and pipeline can still be developed and tested.

Do NOT pretend that mock detections are real AI detections.

Clearly label mock mode as:
"SIMULATION MODE"

ARCHITECTURE REQUIREMENT
==================================================

Design the JavaScript so that the camera source and detection engine are abstracted.

Conceptually:

Camera Source
    ↓
Frame Provider
    ↓
Detection Engine
    ↓
Detection Results
    ↓
Visualization/UI

    ↓
ESP32-CAM Stream

- UI
- detection result handling
- statistics

Create clean functions/modules within script.js to maintain this separation.

==================================================
PERFORMANCE
==================================================

Do NOT run expensive inference unnecessarily on every browser frame.

Separate:

Camera FPS

from:

AI inference FPS

For example:

Camera:
30 FPS

AI:
5 FPS

Use an appropriate inference interval/requestAnimationFrame/request timing strategy.

Display the actual values where possible.

Avoid freezing the browser.

==================================================
ERROR HANDLING
==================================================

The application must fail gracefully.

Examples:

If camera permission is denied:

"Camera access denied. Please allow camera access."

If model loading fails:

"AI model failed to load."

If no detection:

"No plants detected."

Never leave the interface looking frozen or broken.

==================================================
SUCCESS CRITERIA
==================================================

When I open index.html:

1. I see the AGRIVISION interface.
2. I can start my laptop webcam.
3. I see the live camera.
4. The AI detection engine loads if available.
5. Plants are detected with bounding boxes and confidence scores.
6. The dashboard shows detection statistics.
7. I can stop/start the camera.
8. I can stop/start detection.
9. Simulation mode is available if real model inference is not yet configured.
10. The architecture is ready for replacing the laptop webcam with ESP32-CAM later.
